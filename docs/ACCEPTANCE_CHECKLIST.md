# 验收检查清单

> 用途：每次新功能、bug 修复、工单关闭、准备合并前，按本清单验收。  
> 规则：不满足关键项时，不进入 `main`。

## 1. 通用验收门槛

- 已明确本次变更属于影刀、Python、AI 哪一层
- 没有越过既定职责边界
- 对应需求模板、工单或变更说明可追溯
- 输出协议仍兼容 `runner_{run_id}.json`

## 2. 测试与复现

- `python -m pytest tests -q` 全绿
- 能使用对应 `input_{run_id}.json` 本地复现通过
- 如果是 bug 修复，原始失败样例已变为回归测试
- 如果是规则修复，同类边界至少补了 1 个测试

## 3. 运行结果检查

- `runner_{run_id}.json` 已成功生成
- `status` 符合预期
- `message` 可读，且能表达本次结果
- `data.run_id` 与输入一致
- `data.log_path` 有效
- 涉及系统异常时，`crash_snapshot_dir` 或 `crash_snapshot_path` 可追踪

## 4. 边界与安全

- 没有修改影刀职责范围内的逻辑，除非需求明确允许
- 没有写入真实密钥、账号、token、Webhook
- 没有引入个人电脑临时路径
- 没有把测试分支逻辑误带入生产
- 没有破坏现有状态机和异常编码语义

## 5. 文档与说明

- 已更新必要文档或变更说明
- 新增规则已写入需求模板、边界文档或流程文档
- 需要长期保留的异常样例已沉淀

## 6. 分支与发布

- 修复分支命名符合规范，如 `fix/{issue_id}`
- 准备合并到 `main` 的内容已通过验收
- 需要发布时，已更新版本号或 changelog
- 已确认影刀生产环境只运行已发布版本
- 已评估是否需要重跑历史失败任务

## 7. 验收结论模板

```text
验收结论：
- 结果：通过 / 不通过
- 验收人：
- 日期：

检查结果：
- pytest：通过 / 不通过
- 本地复现：通过 / 不通过
- runner 状态：符合 / 不符合
- 回归测试：已补 / 未补
- 文档更新：已完成 / 未完成
- 发布条件：满足 / 不满足

备注：
```
